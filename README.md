# 随机菜单 · Random Menu

独立维护的 React 小程序，面向 Aurai HTML 运行环境。已迁移原 Android 首页的随机挑选与菜单管理，并接通菜谱录入；原 Android 数据尚未导入。

## 与 Aurai 的关系

本项目是 **Aurai 内的「随机菜单」小程序源码仓库**。日常在这里开发 React 页面，构建成单文件 HTML 后交给 Aurai 加载运行；主要交付目标是 Aurai 内的小程序体验。本地浏览器用于开发和预览。

| 项目 | 职责 |
| --- | --- |
| `random-menu-react`（本仓库） | 小程序界面、饮食业务逻辑、宿主桥接调用及 HTML 打包 |
| `../aurai-flutter` | Aurai 宿主，提供小程序入口、HTML 运行环境、应用数据存储及 AI 能力 |
| `../random-menu-flutter` | 独立 Flutter 版本，作为功能迁移与素材参考；不参与本项目的 React 构建 |

两个 RandomMenu 版本不会自动同步代码或数据；浏览器预览的数据也不会自动带入 Aurai。宿主桥接发生变化时，需要同时核对 Aurai 的实现和本仓库的调用。给开发者看的说明维护在本 README，给后续 AI 开发使用的约定维护在 [AGENTS.md](AGENTS.md)。

## 开发与打包

需要 Node.js 22.12+（或 24）及 npm，无需配置环境变量。

```sh
npm install --legacy-peer-deps
npm run dev
npm run build
npm run preview
```

开发地址为 `http://127.0.0.1:5187`，构建预览地址为 `http://127.0.0.1:4187`。端口被占用时会退出，不会占用现有服务。

`dist/index.html` 内联所有 JS/CSS 和 Logo，无 CDN 或运行时资源依赖。使用 hash 路由，无需服务端路由配置。

## 接入 Aurai

```sh
npm run bundle:aurai
```

构建后同步到隔壁 `aurai-flutter` 的 `assets/miniapps/random-menu.html`，复制图标并登记 `catalog.json`。目录不同时可以先构建，再执行 `node scripts/sync-to-aurai.mjs /完整路径/aurai-flutter`。版本使用构建文件的 SHA-256，保持小程序标识不变。

同步目标为：

- 小程序标识：`builtin.random-menu`。
- 页面：`assets/miniapps/random-menu.html`。
- 图标：`assets/miniapps/icons/random-menu.png`。
- 内置小程序目录：`assets/miniapps/catalog.json`，保留其中其他小程序的登记项。

`npm run build` 只构建本仓库；`npm run bundle:aurai` 会进一步修改 Aurai 仓库中的上述资源。同步资源不等于已更新手机中的 Aurai，也不等于发布到小程序库；需要让宿主构建包含新资源，并在 Aurai 内打开验证。

已登记为内置小程序，尚未完成 Aurai 真机宿主内验收。Logo 复用 `random-menu-flutter/assets/branding/app-icon-v1.png` 的骰子餐盘图案。

### 运行时联动

宿主在页面脚本运行前注入 `window.AuraiHTML`。目前已接通 `readData/writeData`：业务数据保存在应用范围内的 `random_menu.json`，包含菜谱、餐厅、菜单、筛选与候选队列。读取返回 `{ revision, value }`，写入携带读取时的 `revision`，避免并发覆盖。页面监听 `aurai:messageupdate` 后重新读取数据；跨页面编辑冲突保留输入并 toast 提示。

独立浏览器没有宿主桥接时，业务数据使用当前来源的 localStorage。两种环境的数据独立，端口变化也会影响浏览器数据的可见范围；宿主读写失败时不会切换到 localStorage。照片缩放后内嵌保存，最多四张；存储失败保留表单并提示重试。

后续 AI 配菜单计划调用 `AuraiHTML.ai.complete`，复用 Aurai 的模型配置，不在小程序中保存模型密钥。该接口提供推理能力，不会自动读取聊天上下文、调用工具或保存业务数据，结果需由小程序确认并写入。目前尚未接入 AI 生成。

对接时可查看 Aurai 的 `lib/src/html_games/html_game_lifecycle.dart`（桥接入口）、`lib/src/html_games/html_ai_script.dart`（AI 桥接）和 `lib/src/agent/html_app_data_tool.dart`（数据与 AI 接口说明）。以当前宿主实现为准。

## 页面

- 随机：按标签偏好/排除筛选、随机挑选、跳过、加入菜单、收藏、暂时隐藏与恢复、轮次完成状态。已选菜品不会重复参与抽取。
- 本次菜单：查看菜谱详情、移除、直接搜索添加菜品、确认清空、继续挑选。
- 菜谱：新建/编辑、最多四张照片、标签、备注与做法、搜索、收藏筛选、详情。
- 餐厅：右下悬浮＋新建，餐厅资料与多分店地址、收藏、搜索；按消费日期、地区、地址关键词、菜系、饭伙和人均筛选。统计入口提供最近到店、到店次数、人均高低和最近添加排序，以及“和谁约饭最多”排行和餐厅钻取。详情支持新增/编辑/删除消费，记录人数、同行者、实际支付、评价、菜品单价/数量/备注/照片及环境照。
- 我的：收藏、想做、想吃、不喜欢、随手记、外观、自动标签及数据备份。
- AI 配菜单：独立流程说明页面，尚未接入生成。

首页以大图展示菜品，点击菜图查看详情；筛选图标后直接显示菜单入口，筛选内容仅在弹层中展开。照片支持上滑加入、下滑跳过、右滑重新抽取，滑动后不会误触详情；所有操作均可通过按钮完成，主按钮完整位于底栏上方。菜单清空收在“更多”中。

不预置演示数据。AI 请求尚未接入。外观可切换跟随系统、浅色、深色，仅在当前会话生效。

餐厅视觉参考与 ImageGen 提示词保存在 `artifacts/design/restaurant-ui-v2.png` 及同名 `-prompt.txt`。小程序全页面右上角留空；搜索、筛选、统计位于标题下方，新增餐厅仅使用右下悬浮＋。餐厅数据保存在现有 `random_menu.json` 的 `restaurants` 字段；旧版仅菜谱文档读取时显式补入空餐厅集合，不改动原有菜谱与菜单。没有服务端数据库结构变更。

餐厅筛选草稿在应用后生效，关闭则保留上次已应用条件；清除筛选保留排序，默认按最近到店排列。地区和地址匹配同一家当前分店，日期与多位饭伙必须匹配同一次用餐（日期含起止当天）；列表次数、人均及统计都按该范围计算，详情始终展示全部历史。人均使用有金额记录的总消费除以对应总人数，零元有效、未填金额不参与；未记录人均的餐厅在价格排序中排后。饭伙姓名用逗号、顿号或换行分隔，同次重复姓名只计一次；排行可搜索、分页并进入相关餐厅，独自用餐与多人未记姓名分开统计。不涉及存储结构变更。

餐厅编辑支持收藏、分店排序、消费记录增改删及菜品排序，修改统一在底部“保存餐厅”后持久化；消费“完成”只回填餐厅草稿。移除分店保留历史地址快照，取消编辑保留已保存的数据。消费可记录具体时间，并选择按单价乘数量持续自动合计；未知单价不会当作零元，手填金额会转为手动。菜品和环境各支持最多 12 张照片、预览、更换、删除及排序，菜品首图为封面。批量照片先生成消费草稿，明确确认后可按 EXIF 拍摄日期分组，无拍摄日期则待手填；所有新增/修改记录在保存时统一校验。照片解析在本地完成，不用文件修改时间替代拍摄时间，也不向地图服务上传位置，尚未接入照片定位地址自动填充。

本次仅在业务 JSON 中增加 `Visit.time`、`Visit.autoCost` 和 `RestaurantFood.images`，保留原封面 `image` 字段；旧数据显式升级，未知时间仍为空、原总额仍按手动保存，单封面转入照片数组。原版资料导入保留消费时间、自动合计状态和全部菜品照片。没有新增数据库表或修改宿主桥接。

## 目录

`src/navigation.ts` 定义页面与导航，`src/components` 维护共享控件及统一线稿，`src/pages` 存放业务页面，首页以本次提供的四屏交互稿为视觉参考，使用浅薄荷背景、白色卡片、绿色主按钮、全宽白色底栏及底部弹层。`src/theme.css` 维护颜色，`src/styles.css` 维护基础样式，`src/home.css` 维护首页及弹层样式。

构建和浏览器核验与 Aurai 真机宿主验收分别记录；浏览器页面正常不代表宿主桥接和设备交互已通过。


## 大照片库导入

Aurai Android 宿主新增 `AuraiHTML.files`，从系统文件选择器流式读取 ZIP，原图独立存放在当前小程序的私有目录。照片不经过 JSON/base64，不生成缩略图；菜谱和餐厅列表每页 12 条，只挂载当前页，图片进入可视区域后才加载，详情可打开原图。

这份旧 Android 桌面备份需要先转换成资料包。转换器仅按表批量读取数据库，不按记录逐条查库；照片逐文件写入 ZIP，内存不会累积整库照片。原始表、设置、草稿及未关联的旧记录保存在资料包 `legacy` 中；当前编辑页面使用转换后的菜谱与餐厅文档。

```sh
npm run prepare:library -- "/Users/luohaitian/Desktop/RandomMenu备份_20261101_153856" "/有足够空间的目录/随机菜单资料.zip" --replace-cover 20200615_212320.jpg=20200708_130434.jpg
```

此封面替换由用户明确指定：将「笋干老鸭煲」缺失的旧封面替换为同一道菜已有的照片。原始备份不修改。默认遇到缺失照片会阻止转换；只有显式传入 `--skip-missing-media` 才跳过，并在 `missingMedia` 留清单。`--metadata-only` 输出小型元数据 JSON，用于核对资料，不会额外复制约 6GB 原图。

在 Aurai 内打开「我的 → 资料导入」选择生成的 ZIP。原始 Android 导出 ZIP 和完整桌面备份目录不能直接当成此资料包导入。已有资料时先确认替换当前显示资料；导入后全部文件和引用校验通过才切换库，之前成功导入的库暂时保留。导入可离开页面，但需保持 Aurai 进程运行；进程终止后会标记中断，重新选择时清理该次未完成的暂存文件。暂不提供运行中取消或断点续传。

宿主提供 `files.info()`、`importArchive()`、`importStatus()`、`listRecords(collection,{query,offset,limit,favorite})`、`readRecord(collection,key)`、`readDocument(name)` 和 `imageUrl(generation,path)`。前端首次发现新库时验证 `random_menu.json`，再按 revision 写入正常业务文档；后续编辑沿用原有存储。元数据保留在内存供菜单搭配使用，分页限制的是 DOM 和图片加载数量，原图仍按需读取。宿主完成导入后广播数据更新，离开导入页也会激活新库。

已核对这份真实备份的 615 道菜谱、180 家餐厅、253 条记录和 1706 张照片，封面替换后无缺失照片引用。尚未做 Aurai 真机文件选择与整库导入验收；完整资料包需额外约 6GB 空间，本轮因本机空间不足未生成。
